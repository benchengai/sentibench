# SentiBench benchmark report

What this measures: how well lexicon, general pre-trained, supervised and LLM
sentiment classifiers label the polarity of software-engineering text on
three published gold sets, what each costs, how stable the LLMs are between
runs, and where they fail. Every number here is generated by
`sentibench report` from the cached runs in `runs/` (not committed); the
tables are not edited by hand. Generated {{generated}}.

## Findings

Numbers are macro-F1 on the LLM test sample ({{sample_n}} items per dataset,
the same items for every classifier) unless a full test split is named;
intervals are 95 % bootstrap intervals.

1. **A logistic regression on general-purpose embeddings, trained on the
   SE train split, is the strongest option where labelled data exists, and
   costs almost nothing to run.** Embeddings + LR: mean 0.83 (full test splits: GitHub 0.86, Jira
   0.77, Stack Overflow 0.85) at $0.0006 per 1,000 items. The best LLM
   setting, `gpt-6.1-terra` few-shot, reaches 0.82, and none of its paired
   differences with Embeddings + LR is distinguishable from zero (GitHub
   +0.035, Jira −0.027, Stack Overflow −0.023). `gpt-6.1-sol` few-shot is
   0.00 to 0.05 lower than Embeddings + LR, with intervals that just reach zero.
2. **Jira separates prompting from training.** Zero-shot LLMs score 0.57 to
   0.68 on Jira against 0.78 to 0.79 for the supervised baselines; the loss is
   in the negative and positive classes (`gpt-6-luna` zero-shot: negative F1
   0.41). Jira's gold follows conventions a generic instruction does not
   convey: thanks for a patch is positive, an apology negative. Nine labelled
   examples recover part of the gap: few-shot adds +0.08 on Jira for
   `gpt-6.1-terra` [+0.04, +0.13], `gpt-6.1-sol` [+0.05, +0.13] and `qwen3:8b`
   [+0.02, +0.13], and little on Stack Overflow.
3. **The larger model is not the better one here.** `gpt-6.1-terra` matches
   or beats `gpt-6.1-sol` in both settings (few-shot: +0.04 on GitHub
   [+0.01, +0.07], +0.02 elsewhere) at about half the price ($0.49 against
   $0.91 per 1,000 items few-shot).
4. **The LLMs agree with each other more than with the gold labels.** Cohen's
   κ between the `gpt-6.1-terra` and `gpt-6.1-sol` settings is 0.83 to 0.88;
   their κ with gold is 0.63 to 0.74. They share a reading of developer text
   that differs from the annotators' in a consistent way, for example calling
   mild frustration in a bug report negative where the gold says neutral. On
   {{noise_n}} sample items, TF-IDF + LR, Embeddings + LR and both
   `gpt-6.1-terra` and `gpt-6.1-sol` settings all agree with each other against
   the gold label.
5. **General-purpose tools misread technical vocabulary; LLMs mostly do not.**
   On the 57 sample items that use words such as "error", "fails", "kill" or
   "problem" and whose gold label is not negative, VADER says negative 81 % of
   the time (8 % on other non-negative items) and RoBERTa-Twitter 49 % (10 %).
   The supervised models and LLMs say negative on 18 to 26 % of them (4 to 9 %
   otherwise); reading those items shows a different error, frustration the
   annotators did not count (below).
6. **A general pre-trained model is a strong free baseline.** RoBERTa-Twitter,
   with no SE training, averages 0.73, level with zero-shot `gpt-6-luna` and
   `qwen3:8b`, and +0.17 over VADER on GitHub and +0.10 on Jira. Tuning
   VADER's two thresholds on dev adds +0.03 to +0.09 to VADER itself.
7. **A local 8B model is close to the cheapest API model.** `qwen3:8b`
   (Ollama, laptop) averages 0.73 zero-shot and 0.75 few-shot at about 0.55 s
   per item, against 0.73 for zero-shot `gpt-6-luna`.
8. **Strict JSON output removed parsing failures.** No LLM call in the test
   runs returned an invalid label: {{llm_failed}} failures in {{llm_calls}} calls
   (schema-constrained decoding through the OpenAI Responses API and Ollama).
9. **Not done: OpenAI credits ran out.** The shared API account ran out of
   credits during the test runs, so `gpt-6-luna` few-shot, the repeated runs
   of the three API models, half of the cross-platform LLM cells and the API
   models' outputs on the demo's example sentences are missing (listed under
   "Runs not done"). No numbers were estimated for them; the findings above
   use only completed runs.

## Setup

### Datasets

{{datasets}}

- **GitHub**: pull-request and commit comments, annotated by three of the
  authors following the Stack Overflow guidelines (Novielli et al. 2020). No
  split is published, so it is split 70/30 with stratified sampling (seed
  2026), the same proportions the authors used. The CSV wraps each text in an
  extra quote level (a stray trailing `"`, doubled inner quotes); this is
  undone before use.
- **Jira**: issue comments from Ortu et al. (2016), labelled with emotions
  and mapped to polarity (love, joy → positive; anger, sadness, fear →
  negative; surprise discarded; no emotion → neutral), in the train/test
  partition distributed with EMTk. One empty test text is dropped. 111 test
  texts also occur verbatim in train (short ones such as "Thanks!", "My bad."
  and "I just committed this."; median 14 characters), which flatters
  supervised models on Jira.
- **Stack Overflow**: questions, answers and comments from Calefato et al.
  (2018), with the official Senti4SD train/test partition.

All three use the same emotion-based scheme (Shaver et al. 1987), but not the
same conventions at the edges: Novielli et al. (2020) note that Jira labels
thanks for a patch as positive and "polar facts" ("this might be a bug") as
negative, where the GitHub and Stack Overflow raters treat routine politeness
and factual problem reports as neutral.

### Classifiers

| Classifier | What it is | Trained on SE data |
|---|---|---|
| VADER | General-purpose lexicon with rules (Hutto & Gilbert 2014); compound score ≥ 0.05 positive, ≤ −0.05 negative | No |
| VADER, dev-tuned thresholds | The same scores with the two thresholds chosen on each dataset's dev split | Thresholds only |
| RoBERTa-Twitter | `cardiffnlp/twitter-roberta-base-sentiment-latest` (Loureiro et al. 2022), fine-tuned on tweets, run off the shelf on CPU | No |
| TF-IDF + LR | Word uni- and bigrams, sublinear tf, logistic regression; C and class weights chosen on dev, refitted on train | Yes |
| Embeddings + LR | `text-embedding-3-small` vectors with a logistic regression head; C and class weights chosen on dev, refitted on train | Yes (head only) |
| LLMs | `gpt-6-luna`, `gpt-6.1-terra`, `gpt-6.1-sol` through the OpenAI Responses API with a strict JSON schema (`{"label": "negative" \| "neutral" \| "positive"}`) and reasoning effort `low` (the lowest setting all three accept); `qwen3:8b` locally through Ollama with schema-constrained decoding and reasoning off (the model's default sampling: temperature 0.6, top-p 0.95, top-k 20). One item per call, provider default sampling | Few-shot: {{shots}} examples in the prompt |

SentiStrength-SE and Senti4SD were not run. Neither has a Python package:
Senti4SD's classifier runs through R scripts and Java jars and needs a
word-embedding file fetched with Git LFS (per its repository), and I found no
official download for SentiStrength-SE. TF-IDF + LR is the same family as
SentiCR (bag of words with a supervised classifier).

### Protocol

1. **Dev first.** Each train split has a stratified 20 % dev part. VADER's
   thresholds, the supervised models' hyperparameters and the LLM prompts were
   chosen on dev only.
2. **Prompt selection rule, fixed before test.** Per model, the zero-shot and
   the few-shot prompt variant with the highest mean dev macro-F1 across the
   three datasets. `gpt-6-luna` and `qwen3:8b` were compared on 150 dev items
   per dataset, `gpt-6.1-terra` and `gpt-6.1-sol` on 60 (cost).
3. **Test once.** The selected configurations were then run on test, once.
   No model, prompt or setting was changed after test scores were seen. The
   RoBERTa model was added after the other baselines had been scored, with no
   settings to tune. The error-analysis tags, the paired comparisons and the
   sarcasm marker search were defined after the test runs; they describe
   results and choose nothing.
4. **Samples.** The cheap classifiers (VADER, RoBERTa, TF-IDF, embeddings,
   `gpt-6-luna` zero-shot) were scored on every test item; the full-test
   `gpt-6-luna` few-shot run is not done (OpenAI credits ran out). All classifiers, including
   `gpt-6.1-terra`, `gpt-6.1-sol` and `qwen3:8b`, were scored on the LLM test
   sample: the first {{sample_n}} items per dataset of a fixed stratified order of the
   test split, so every row of the main table is on the same items. The
   variance runs repeat each LLM twice more on the first {{variance_n}} of those.

### Metrics

- **Macro-F1** (the unweighted mean of the per-class F1 scores; the standard
  measure in this literature because Jira is two-thirds neutral) and
  **Cohen's κ** against gold, each with a 95 % percentile bootstrap interval
  over items (1,000 resamples).
- **Paired differences** between two classifiers on the same items, with a
  paired bootstrap interval.
- **Failures** (invalid or truncated JSON, a refusal) count as wrong answers
  and are never credited to a class. API errors that outlast four retries
  (rate limits, outages, an empty account) say nothing about the model: those
  items are treated as not yet run and are picked up by the next resume.
- **Cost** from the published per-token prices as of {{prices_as_of}}
  ({{prices_source}}): {{prices}}
  per million input / cached input / output tokens; `text-embedding-3-small`
  $0.02 per million. Local models have no per-item price; their cost is time.

## Prompt selection on dev

{{prompt_dev}}

Two things stand out. First, the guided prompt helps the small models and
hurts the large ones on Jira: `gpt-6-luna` and `qwen3:8b` gain +0.04 to +0.05
mean dev macro-F1 from it, while `gpt-6.1-terra` and `gpt-6.1-sol` drop from
0.86 and 0.82 to 0.49 and 0.57 on Jira dev. Reading `gpt-6.1-sol`'s
disagreements between the two prompts, it applied rule 2 (routine politeness
does not decide the label) literally: "Committed thanks Jingwei." and "sorry." became neutral, where
Jira's gold says positive and negative. Second, the few-shot variant without
rules (`fs-basic`, added after this first dev round) is the best variant for
both large models. Few-shot examples carry a dataset's conventions better than
written rules.

## Cross-platform: train or tune on one dataset, test on another

{{cross}}

TF-IDF + LR loses 0.14 to 0.35 macro-F1 when it is trained on one dataset
and tested on another (worst: Jira to Stack Overflow, 0.79 to 0.44), as
Novielli et al. (2020) found for bag-of-words tools. Embeddings + LR loses
0.04 to 0.16. For `gpt-6-luna`, few-shot examples from another dataset scored
+0.01 to +0.04 above its zero-shot prompt on the target (GitHub examples on
Jira 0.61, on Stack Overflow 0.82; Jira examples on GitHub 0.84; zero-shot:
0.57, 0.81 and 0.80). The within-platform few-shot cells and the Stack
Overflow-source cells are marked "–": not done, OpenAI credits ran out.

## Cost, latency and failures

{{cost}}

LLM latency is the wall time of one call with six to eight calls in flight
from a laptop on home broadband; `qwen3:8b` ran one request at a time on an
Apple M5 laptop with 16 GB that other work was also using. Local baselines are
batch throughput on the same laptop's CPU.

## Run-to-run variance

{{variance}}

Only the local model's repeated runs were completed. The three API models'
repeated runs are not done: OpenAI credits ran out (see "Runs not done"). With its default sampling
(temperature 0.6), `qwen3:8b` changed the label of 4 of 300 items (1.3 %)
zero-shot and 10 of 300 (3.3 %) few-shot across three runs. Mean macro-F1
moved by 0.003 zero-shot and 0.03 few-shot. That is smaller than the sampling
intervals (about ±0.05), but a single few-shot run can differ from the next by
as much as some of the paired differences above, so one-run comparisons of
close models should be read with that in mind.

### Strong models agree, gold differs

{{noise_n}} items of the LLM test sample have TF-IDF + LR, embeddings + LR,
`gpt-6.1-terra` and `gpt-6.1-sol` agreeing with each other against the gold
label.

{{examples_noise}}

What the examples show:

- **Technical vocabulary.** VADER's errors are literal: "OK, problem happened in
  the CI server yesterday." is negative to it because "problem" is in its
  lexicon. The LLMs' errors on the same tag are a different kind. They call
  negative what reads as mild frustration to them and as a neutral report to the
  annotators ("I completely don't understand why such an unrelated thing breaks
  navigation", "this may be very painful", "a devastating error"). Several of
  those gold labels are debatable.
- **Politeness.** The gold sets treat it differently. In this sample 35 of
  37 politeness items on Stack Overflow are positive, while on Jira the split
  is 39 positive, 23 neutral, 23 negative (apologies are negative there).
  Zero-shot LLMs are weakest on Jira politeness (`gpt-6-luna` 0.39 accuracy);
  few-shot brings `gpt-6.1-terra` to 0.78. The supervised baselines, which
  learn each dataset's convention, are at 0.72 to 0.73 on Jira.
- **Sarcasm.** The tag (gold negative, VADER compound ≥ 0.5) found 15 items,
  and on reading none of them is sarcastic. They are criticism or disagreement
  in positive or polite words ("I do see some benefits. But I think the
  negatives greatly slap the benefits off the table."). VADER calls all 15
  positive; the LLMs get 8 to 11 right. Sarcasm proper is rare in these gold
  sets. A search of the negative test items for markers ("nice", "great",
  "yeah right", "/s") found two clear cases, both in the sample, and every
  classifier except TF-IDF + LR, which keys on "nice", labels them negative.
  Both also contain explicit negative words:

{{examples_sarcasm_real}}

- **Gold disagreements.** In the {{noise_n}} items where the strong models agree against
  gold, the gold label is often defensible as a convention ("[~ashutoshc]
  Thanks." is neutral in Jira) and sometimes debatable ("SCSS is not better
  than SASS, just different." is gold positive). The gold labels were not
  changed.

## Limitations

- **Text, not people.** The benchmark classifies the polarity of text
  artefacts. It produces no per-person scores and should not be used to infer
  how individual developers feel: AI emotion recognition of workers is
  prohibited in the EU workplace (AI Act, Art. 5(1)(f)), and expressed
  sentiment is a cue, not a readout of an inner state (Barrett et al. 2019).
- **Samples.** The expensive models were scored on {{sample_n}} test items per dataset.
  Bootstrap intervals over items are about ±0.05 macro-F1 at that size, so
  differences under about 0.05 between two models are not resolved by this
  benchmark (see the paired intervals).
- **Small dev sets for the expensive models.** Prompts for `gpt-6.1-terra`
  and `gpt-6.1-sol` were chosen on 60 dev items per dataset; a different dev
  sample could have picked a different variant for the zero-shot setting.
- **Conventions, not just accuracy.** Each gold set encodes its annotators'
  conventions. An LLM prompted with a generic instruction is scored against
  conventions it was never told; few-shot examples transfer some of them. The
  "strong models agree, gold differs" list shows items where the gold label is
  debatable or follows a convention; gold was not changed.
- **Splits.** The GitHub split is ours (seeded), not the authors', so numbers
  are not directly comparable with published GitHub results. Jira test overlaps
  train (111 texts), which flatters the supervised models there.
- **Model drift.** API models can change behind the same name; results are
  from runs between 2026-11-02 and the generation date above.
- **Tags are heuristics.** The error-analysis tags select candidates with
  surface patterns; the sarcasm tag in particular also catches mixed messages.
  The examples were read by hand before the findings above were written.
- **Not run:** SentiStrength-SE and Senti4SD (no Python package, see above);
  fine-tuning a transformer on SE data (Zhang et al. 2025 show fine-tuned small
  models stay strong when training data is ample and balanced).

## Reproduce

```bash
uv sync --extra hf
uv run sentibench fetch && uv run sentibench prepare
uv run sentibench baselines --roberta
uv run sentibench llm -m openai:gpt-6-luna ollama:qwen3:8b -p zs-basic zs-guided fs-basic fs-guided --split dev -n 150
uv run sentibench llm -m openai:gpt-6.1-terra openai:gpt-6.1-sol -p zs-basic zs-guided fs-basic fs-guided --split dev -n 60
# then the selected prompts on test (see README), and:
uv run sentibench examples && uv run sentibench report
```
